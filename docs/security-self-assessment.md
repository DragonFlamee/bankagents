# 安全自评报告

评估范围为Windows本机、单worker和合成账户。201项项目测试包含18项预约到期专项，结果见[JUnit记录](../evals/results/pytest.xml)。浏览器证据与版本范围见[测试说明](evaluation.md)。

## 控制与证据

| 控制 | 实现 | 验证依据 |
| --- | --- | --- |
| 绿色读取 | 会话确定归属，查询所属数据 | `test_api.py`、`test_bank.py` |
| 黄色确认 | 固定详情，本人确认后才提交 | 未授权零副作用、参数绑定和金额边界用例 |
| 红色验证 | 操作与挑战绑定，期限、单次消费和失败锁定 | OTP归属、重放、过期和锁定用例 |
| 预约付款 | 实际执行日累计超1000元暂停并验证，每月每期独立 | `test_scheduled_authorization.py`及[浏览器记录](../evals/results/scheduled-auth.json) |
| 幂等与事务 | 同键参数绑定，银行事务复核累计与记账 | 并发、累计升级和原操作对账用例 |
| 注入约束 | 严格字段、工具白名单和服务端权限 | 非法计划、伪造身份与恶意备注用例 |
| 幻觉约束 | 回答使用工具事实及回执 | `test_answers.py`与unknown用例 |
| 人工接管 | 停止计划授权，操作员仅能交还控制权 | `test_operator.py`、`test_orchestrator.py` |
| 审计 | 关联业务标识，清洗敏感字段，hash链 | 审计清洗与局部篡改检测用例 |
| 数值隔离 | 白名单DSL、独立worker与资源限制 | `test_sandbox.py` |

预约累计验证已补齐。原先“普通300元后执行1000元预约”的用例，现在在验证前保留300元累计，验证后恰为1300元。专项测试还覆盖月度预约、重复调度、取消、过期、故障、对账及旧数据库迁移。

## 已知风险

| 风险 | 当前范围与后续工作 |
| --- | --- |
| 认证为演示实现 | 默认口令公开，同应用OTP可读；真实部署需独立认证服务及威胁测试 |
| 新增六场景模型验收不足 | 历史15例为早期开发集，未构成当前六场景开放表达或重复可靠性证据 |
| 订阅授权口径 | `subscriptions.get`为黄色，周期识别`detect`为绿色分析；需在比赛材料中说明与题目“订阅查询”示例的区分 |
| 多worker与跨库恢复 | 进程内锁不提供分布式租约，银行库与计划库不同时提交；需租约及崩溃注入测试 |
| 审计缺少外部锚 | 无法充分发现删尾或整体重算；需签名、独立存储、访问控制和备份 |
| 公网入口未加固 | 请求体限制、连接与速率控制、TLS/Host策略仍需补齐；目前监听本机地址 |
| 隔离能力有限 | 仅允许数值DSL；POSIX资源限制未实测，不能开放任意Python执行 |
| 欺诈与产品均为模拟 | 异常只是待核对线索，未训练欺诈模型；理财产品及收益不用于真实决策 |
| 缺少真实银行运营能力 | 未接入银行、商户、外部资金冲正或完整生产运维 |

自动化测试说明已覆盖用例下的行为，不能替代真实认证、未知攻击、目标平台或生产安全验收。
