# Agent 工作台与行动记录

2026-10-22。页面以任务执行现场为中心：左侧按事件发生顺序展示行动，右侧展示已校验的任务依赖、授权卡片和业务回执。账户概览与六类业务入口收纳在可展开区域中。

## 实际执行链路

1. 用户提交目标，`POST /api/runs` 创建用户所属的执行记录并立即返回 202。
2. 后台请求规划器。页面通过增量轮询获取 `model.started`，此时尚未创建业务计划。真实模型响应后显示耗时、HTTP 状态、Request ID 和 Token 用量。
3. 校验工具白名单、参数与无环依赖，通过后保存计划。
4. 按依赖调用工具，记录实际输入和返回观测。写操作的准备阶段仅创建待授权操作，不表示资金已经提交。
5. 遇到确认或验证关卡停止推进；用户在操作卡片或独立验证面板授权。
6. 银行服务返回回执后更新节点，继续执行依赖它的后续步骤。结果未知时查询原操作，不能直接再次扣款。

当前每个请求进行一次模型规划，后续沿持久化 DAG 执行。暂停和恢复不会产生额外模型轮次；尚未实现基于每次观测的多轮自主重规划。界面展示可核对的行动，不保存或展示模型的私密思考文本。

## 接口与恢复

| 接口 | 用途 |
| --- | --- |
| `POST /api/runs` | 提交目标；沿用登录、角色与 CSRF 检查 |
| `GET /api/runs` | 当前用户最近 20 条执行摘要 |
| `GET /api/runs/{id}?after={seq}` | 用户所属的执行、当前计划及增量事件，单次最多 200 条 |
| `POST /api/runs/{id}/cancel` | 请求停止规划后的工具，或取消未执行节点 |

事件与执行状态存储在 `agent.sqlite3`。刷新页面恢复选中的执行记录，不重新请求模型或重放工具。当前模型 HTTP 请求不能被即时撤回；规划中停止会等待请求返回，再阻止后续工具。进程重启将未停稳的记录标为 `interrupted`，不会自动重发。已提交交易不因取消任务撤销；未知结果需要先对账。当前只支持单 worker，本实现不提供分布式任务租约。

事件序号、时间与工具参数来自后端。验证码、密钥、授权头、会话令牌和 `reasoning_content` 从事件字段递归排除。Token 用量如服务商未返回会显示缺失；思考 Token 是输出的子集，不能重复累计。旧同步任务没有历史执行事件，不能补造为实时轨迹。

## 验证与演示

- 项目 `tests` 目录 140 项通过，含停止规划、增量事件、依赖授权续跑、跨用户隔离、CSRF、重启中断、刷新持久化及真实模拟验证码脱敏检查。1 项既有 Starlette HTTPX 弃用提醒。
- 本轮真实 qwen3.8-flash 思考模式浏览器 6 组验证通过：规划期间返回增量状态、三节点授权续跑、刷新不重放、停止后零工具调用、原操作对账及 390px 布局。
- [浏览器证据](../evals/results/agent-workflow-browser.json)包含实际 API 请求元数据、执行事件与源码摘要；[首次录制失败](../evals/results/agent-workflow-first-attempt.json)保留错误故障夹具名称，后改用已有 `timeout_after_commit` 模式。该失败发生在演示脚本，前三步业务与停止检查已通过。
- 新[演示视频](../demo/tracebank-agent-workflow.webm)约 103 秒，无真人配音，原始验证码不显示。全部银行数据、资金、授权与故障均为合成夹具；不构成人类体验实验或开放攻击安全证明。

推荐现场输入：“先分析本月账单，然后给李娜转300元，最后挂失尾号1024的卡片”。先看左侧模型与工具事件，再核对右侧授权；转账确认后观察挂失节点继续。再次演示挂失前应使用新数据目录，或先解挂演示卡片。
