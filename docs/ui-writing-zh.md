# TraceBank 中文 UI Writing Rules

1. 页面标题用名词说明去向；任务标题说明实际业务。只在导航保留 Agent 工作台，不追加可追溯/智能/高效等口号。
2. 按钮写明动作和对象：确认转账、核对并验证、查询原操作、查看执行详情。取消任务不称撤销交易。
3. 一个标签表达一个概念。不同字段用 dl/dt/dd、标题或列表分层，不用 A·B、A/B 拼成小字。日期、数额、实际比例及快捷键中的符号保留。
4. 一级说已发生什么、现在要做什么；步骤/时间/回执放二级；内部ID、工具代码、请求ID、原始JSON、模型用量放三级。
5. 每个任务一级只显示一次状态。节点的独立状态只在展开步骤中显示；审批列表中的每项操作可各有状态。
6. 只按服务端事实写“已完成”“未执行”“已取消”。任务取消不会撤销已提交业务；未知结果必须写待核实并只查原操作。
7. 等待授权必须保留收款人、金额、付款账户、卡片/业务、风险含义和有效期。身份验证放独立窗口，不通过聊天表达授权。
8. 重要警告写明后果；错误写明结果和安全下一步。技术错误原文可查，不主导一级界面。
9. 全局一处模拟环境标识；金融授权和登录处保留必要模拟/认证边界。不将演示认证写成真实银行认证。
10. 空态说明当前真实情况，并给一个可执行入口。不加填充口号、无意义英文眉题或装饰性进度。
11. 同一概念固定称谓：任务、执行详情、技术日志、付款账户、收款人、业务回执。技术工具名保留在日志，不取代业务名称。
12. 不为精简删除账单结论、风险说明或已发生交易。已识别ID的移出必须保留完整原文和依据入口。

依据：[Atlassian 写作规则](https://atlassian.design/foundations/content/language-and-grammar)、[NN/g 必要信息原则](https://www.nngroup.com/articles/aesthetic-minimalist-design/)、[GOV.UK Details](https://design-system.service.gov.uk/components/details/)。本项目根据中文金融办理语境应用，不照搬英文语法。
