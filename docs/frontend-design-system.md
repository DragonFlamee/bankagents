# 拾迹银行界面设计系统

2026-10-26说明：本文件记录上一版frontend-design改造及其历史截图，不作为当前10视图与新增场景的唯一规范。当前渲染与问题见[网页检查](review-20261026.md)。当前版本已按用户新要求取消绿色品牌色，现行规则见 [Premium MASTER](../design-system/tracebank-premium/MASTER.md)，最新代码、截图和验收见 [Premium UI QA](premium-ui-qa.md)。下文旧色值与测试记录用于追溯，不作为当前主题规范。

2026-10-22。用途是办理可核对的模拟银行业务：用户查看账户、向 Agent 提出目标、核对敏感操作并追踪回执。目标用户是个人银行演示用户与比赛评审，不把个人账户伪装成真实企业资金系统。

## 方向与设计标记

方向：清晰账本与可追溯任务。金融数据以对齐和数字排版建立秩序；Agent 的真实执行轨迹形成一条细墨绿引导线。其余结构保持安静。

| 标记 | 值 | 使用 |
| --- | --- | --- |
| Canvas | `#F6F8F9` | 应用底色 |
| Surface | `#FFFFFF` | 内容与工作区 |
| Ink | `#1C292E` | 主文字、金额 |
| Muted | `#6F7D83` | 说明、次级信息 |
| Line | `#E3E9EC` | 分区、表格边界 |
| Jade | `#176B55` | 品牌、主操作、完成状态 |

警示与失败使用独立语义色；不把不同业务模块涂成不同颜色。Latin 与金额采用本地打包的 Manrope，中文采用系统 UI 黑体。正文 14px，说明 12px，页面标题 26–28px，核心金额 30px；金额使用 tabular numbers。间距基于 4px，主要布局间距 24px，内容面板内距 24px。控件圆角 6px，内容圆角 10px，避免所有元素共享同一胶囊外形。

## 信息架构

```
固定导航 218px       页面标题、日期、刷新 / 新任务
总览                一条账户指标带
Agent 工作台        主图表与分类分布 / 任务列表、待确认摘要
财务分析
审批中心            工作台：目标 -> 思考与工具 -> 回答
活动日志                    固定输入区       计划与授权侧栏
```

总览承担账户与任务入口；工作台承担目标、执行和回答；财务分析展示已有交易与分类；审批中心汇集原有待确认、待验证与待核实操作；活动日志展示任务与审计事件。默认进入总览，可直接进入工作台。移动端导航收进抽屉，表格在自己的区域横向滚动，不让整页溢出。

## 关键交互

- Agent 处理时展开真实事件，回答完成后收起；手动展开选择保留。最终回答在过程下方。
- 黄色操作核对后确认，红色操作进入独立验证面板；未知结果查询原操作，不默认再次执行。
- 暂停、恢复、取消未执行步骤与转人工沿用现有接口；审批不覆盖这些限制。
- 图表来自现有模拟交易，不生成随机走势或虚构环比。筛选、搜索、任务打开、刷新与空状态都有实际行为。
- 六类业务入口保留功能范围；理财、预约、AA、资金冻结等未实现能力继续如实标明。

## 实现与审查计划

React + TypeScript + Tailwind CSS，静态构建交给现有 FastAPI 同源服务。保留身份、CSRF、权限与银行服务；分析页只读适配现有查询方法。自托管字体，不依赖第三方字体请求。

构建前审查：原方案中重复的大圆角卡片、英文眉题、弱对比小字与大量绿色底色会使金融内容像模板。修订为单条指标带、不同密度的真实图表和表格、与审批相邻的任务轨迹；不加装饰性插画、渐变或玻璃效果。

完成后运行浏览器，检查五个页面、授权与验证、任务生命周期、390px/768px 响应式与键盘交互。至少进行一轮截图批评与修订，记录实际问题、修改及复验结果。

## 实际视觉审查与修改

第一轮已实际启动独立 FastAPI 演示服务，并用 Edge 截图：[总览](../artifacts/screenshots/ui-redesign/iteration-1/dashboard.png)、[工作台回答](../artifacts/screenshots/ui-redesign/iteration-1/workspace-result.png)。主要问题是小字过多、次级文字对比偏弱，以及种子交易集中在少数日期时按日聚合只剩单点。部分字体被构建器内联为 data URL，与原有 CSP 冲突。

第二轮提高业务正文到 14px、表格与导航到 12–13px，增强业务文字对比，减少无用途英文眉题和宣传式标题。图表改成实际支出交易序列的累计图，明确标注横轴含义，不虚构跨日走势；手机端改用更窄的 SVG 坐标系，避免标签缩得过小。字体改为同源独立文件，保留原 CSP。抽屉补充键盘焦点约束、Escape 关闭与关闭后不可聚焦处理。

最终页面见 [总览](../artifacts/screenshots/ui-redesign/iteration-2/02-dashboard.png)、[Agent 回答](../artifacts/screenshots/ui-redesign/iteration-2/04-workspace-answer.png)、[展开工具链](../artifacts/screenshots/ui-redesign/iteration-2/05-tool-chain.png)、[审批](../artifacts/screenshots/ui-redesign/iteration-2/06-approvals.png)、[交易分析](../artifacts/screenshots/ui-redesign/iteration-2/08-analytics.png)、[390px 分析页](../artifacts/screenshots/ui-redesign/iteration-2/10-analytics-390.png)。截图均来自合成账户，验证码截图做遮罩。

验收证据分开记录：153 项 Python/HTTP 回归通过；[新 UI 实机交互](../evals/results/fintech-ui.json)使用全新离线模拟服务，验证真实余额变化、授权、错误验证码、暂停、操作员交还、六个快捷场景、筛选导出与 768px/390px 布局；[生成时序检查](../evals/results/react-thinking-ui.json)采用历史真实响应的受控夹具，检查规划、工具、整理回答阶段不提前显示结果，以及手动折叠和失败状态。本轮 UI 验收不冒称新增真实模型测试。

新增的是现有业务的界面组织及查询展示：只读 `/api/analytics` 组合原有流水与分析方法；未改变资金权限、确认、验证、幂等、对账或工具范围。六个 UI 快捷入口不是赛题六个方向全覆盖：理财、预约、AA、冻结资金仍未实现。

现有数据兼容检查发现，历史列表中的旧任务未必保存新版本回答；详情接口可依据已保存结果补全。前端现已保留详情中的回答，避免列表刷新覆盖。实际打开用户原省钱任务、核对历史模型用量并刷新验证，不重新调用模型或执行业务，证据见 [fintech-live-compat.json](../evals/results/fintech-live-compat.json)。
