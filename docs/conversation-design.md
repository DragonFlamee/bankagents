# 连续对话工作台方案

2026-10-22，基线27ee36c。对象为使用合成账户查询和办理银行业务的个人用户。问题是每轮任务替换正文，历史不可见，输入区随回答滚走，已选择场景无持续标识，执行阶段只给静态入口。

选定方向：金融顾问式对话。保留深导航与浅正文，内容宽度760px；用户消息靠右，助手正文靠左，金融核对字段使用必要边界；工具过程在回答前以轻量状态行组织。与大面积聊天气泡/彩色卡片的方案相比，主体仍是易读的业务文本和可核对授权，不堆聊天装饰。用户明确希望采用主流AI的连续交互，本轮据此调整此前单任务布局。

```
深色导航        对话定位
最近对话        ┌ 可滚动消息区 ──────────────────┐
                │                  用户需求      │
                │ 银行标记  正在规划 · 实际耗时  │
                │   实际工具动作 / 可展开详情    │
                │   回答、必要授权              │
                │                  继续追问      │
                │ 银行标记  下一轮过程和回答     │
                └───────────────────────────────┘
                [目标图标 储蓄目标 ×] 输入需求
                [场景图标 选择场景]         发送
```

设计检查：使用主流AI的消息顺序和输入习惯，保留TraceBank金融身份、深导航和明确授权；不复制具体产品皮肤。颜色保持#142235导航、#FFFFFF正文、#F5F7FA辅助面、#0A2540文字、#635BFF操作、#53677B次文。Manrope数字+系统中文，正文16px/1.85，用户消息15px，过程13px，间距8/12/16/24/32。品牌改为简洁的银行柱廊与路径标记SVG，不使用文字徽章或泛用机器人。

实现顺序：会话持久化读取与续问 → 每轮独立消息/过程/授权 → 场景图标和模式chip → 排版与底部输入 → 实际浏览器复核。正在执行时仅动画化状态图形，正文保持不透明；只展示可观察的执行信息，不展示私有思考内容或编造推理步骤。保留减少动态效果。

会话来自服务端已保存的run/plan，跨刷新恢复；用户归属校验不可因新接口弱化。历史未完成授权保持可处理，下一轮不会默认同意；编辑待执行转账仍由原后端取消旧授权。新对话清空当前上下文，切换账户不得带入消息。模式chip只是输入上下文提示，实际工具与权限以服务端计划为准。
